# Audit WIPP — 2 octobre 2026

Audit du code (`native/` + API `src/`) comparé au cahier des charges A→Z, recoupé avec la **vraie base Supabase de production** (lecture seule).
Les chiffres « en base » montrent ce qui a réellement été utilisé en production, pas seulement ce qui existe dans le code.

> Limite : rien n'a été testé sur un téléphone pendant cet audit. « Code présent » ≠ « fonctionne ». Une fonction avec 0 ligne en base n'a jamais abouti en production.

**Légende** — ✅ branché au serveur et utilisé · 🟡 code présent mais jamais prouvé en prod (0 donnée) ou incomplet · 🎭 démo / local uniquement · ❌ absent · 🔴 problème à corriger

## Santé générale

- TypeScript de l'app native : **0 erreur** (`npx tsc --noEmit`). 11 fichiers de tests unitaires.
- Base : 42 tables, RLS activé partout. Aucune alerte de sécurité critique côté Supabase.
- API `wippapp.com/api/wipp` en ligne, LiveKit configuré.
- Utilisation réelle : 10 profils (dont **2 seulement liés à Firebase**), 1 conversation, 8 messages, 3 appels, 11 Stories, 1 carte pro, 2 événements.

## Autres constats techniques

- **Données de démo dans l'app** : utilisateurs, conversations, Stories, boutiques et pharmacies de démo sont chargés au démarrage. La plupart sont effacés à la connexion au serveur, sauf les 2 fausses conversations ci-dessus.
- **Site wippapp.com ≠ app native** : ce sont deux applications distinctes. Les écrans de `native/` n'apparaissent jamais sur le site.
- **Mise en ligne manuelle** : pousser sur GitHub ne met pas le site à jour. Il faut `npm run publish` (tokens Vercel / Expo).
- **`npm run dev` à la racine est cassé** : la base locale de test ne sait pas appliquer les migrations Supabase (rôle `authenticated`, schéma `wipp_private`).
- Code mort : `native/src/lib/server-fn.ts` (jamais appelé).
